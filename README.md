# peptidly-website

Public marketing and legal site for the [Peptidly](https://peptidly.co.uk) Android app.
Hosted on GitHub Pages, served from `peptidly.co.uk`.

This repo intentionally has **zero dependencies** — it's plain HTML, CSS, and one
build script that uses only built-in Node modules. Pushing to `main` deploys via
GitHub Pages with no build step on the GitHub side.

## Layout

```
peptidly-website/
├── README.md                       ← you are here
├── CNAME                           ← peptidly.co.uk (tells GitHub Pages the domain)
├── .gitignore
├── index.html                      ← landing page (hand-written)
├── home.css                        ← landing page styles
├── home.js                         ← landing page script: calculator, Home screen demo, motion
├── calc.js                         ← reconstitution arithmetic, ported from the app
├── picker.js                       ← the site-rotation demo's rules (history, suggestion, states)
├── style.css                       ← styles for the legal pages
├── privacy.html                    ← generated by build script
├── terms.html                      ← generated by build script
├── health-disclaimer.html          ← generated by build script
├── assets/fonts/                   ← Inter and JetBrains Mono (latin, variable), self-hosted, OFL
└── scripts/
    ├── build-from-content.mjs      ← reads ../Peptides/helix/legal/content.ts → renders the three .html files
    ├── build-body-map.mjs          ← writes the body map into index.html from the app's geometry
    ├── check-calculator.mjs        ← checks calc.js against the app's own functions
    ├── check-no-doses.mjs          ← fails if a dose figure appears on the page
    └── check-sites.mjs             ← checks picker.js against the app's rotation rules
```

## Updating the legal text

The legal documents are **derived** from `helix/legal/content.ts` in the
sibling [Peptides repo](https://github.com/<your-username>/Peptides). Editing
the `.html` files directly will get overwritten on the next build.

To update:

```bash
# 1. Edit the constants in the app repo
cd path\to\Peptides\helix
# ... edit legal/content.ts ...

# 2. Re-run the build script in the website repo
cd path\to\peptidly-website
node scripts/build-from-content.mjs

# 3. Commit and push the website repo
git add privacy.html terms.html health-disclaimer.html
git commit -m "update legal text"
git push
```

GitHub Pages picks up the new commit within a minute.

## Updating other pages

`index.html` is hand-written. Edit it directly if the landing copy changes. Its styles are in
`home.css` and its script in `home.js`; the legal pages keep `style.css`. No preprocessor, no build.

The interface pieces on the landing page (the calculator, the Home screen, the schedule panel, Home
before the first cycle) are drawn in HTML from the app's current screens and carry `data-ui`. When the app's
look changes, update them to match; they are not screenshots and will not update themselves.

## The calculator

The calculator on the landing page must compute what the app computes. Its arithmetic lives in
`calc.js`. After any change to it, or to the app's reconstitution code, run:

```bash
cd path\to\peptidly-website
node --experimental-strip-types scripts/check-calculator.mjs
```

It compares several thousand inputs, figure by figure, against the app's own functions in the sibling
Peptides repo and exits 1 on any difference. Where a figure cannot be computed from what was entered,
the page shows an em dash, and it shows the concentration before a dose is entered. The app's
calculator screen shows zeros in those states instead. The page never fills in a dose: the dose field
starts empty.

The site shows no dose. In the app replicas every dose and draw, and the low-stock banner's vial size,
is a `.mask` chip: blurred stand-in 8s that come from CSS (`data-d`), so without styles the chip is empty
rather than a figure. A caption under the Home screen says amounts are blurred. The hero calculator keeps
its example vial (10 mg, 2 ml, 5.00 mg/ml), which is the visitor's input, not a dose. To check:

```bash
node scripts/check-no-doses.mjs
```

It scans every `.html`, `.js` and `.css` file at the site root and exits 1 on a number followed by mcg,
mg, ml, units, U or IU (in HTML, also across tags and `&nbsp;`), or on a mask holding anything but 8s.
Allowed: "1 ml insulin syringe", "3 ml vial", the hero vial's "10 mg" label and concentrations (mg/ml).
It reads literal text only, so a figure assembled in JavaScript would get past it.

## The site-rotation picker

The body map in "Every site, remembered" is generated from the app's own geometry and drawing
(`helix/lib/dose-log/bodyGeometry.ts`, `components/dose-log/BodyMap.tsx`). After the app's map changes,
or after editing the demo in `picker.js`, run both, from this folder:

```bash
node --experimental-strip-types scripts/build-body-map.mjs
node --experimental-strip-types scripts/check-sites.mjs
```

The first rewrites the map between the `body-map` markers in `index.html`, with the demo's first state
baked in. The second runs the app's rotation and body-map code on the demo's history and exits 1 if the
page's suggestion, skipped line, switched-off areas, rest window, any area's colour for any pick, or a
warning differs from the app's. Both need the sibling Peptides repo.

## Local preview

The site is pure static HTML, so any local server works:

```bash
cd path\to\peptidly-website
python -m http.server 8000
# open http://localhost:8000
```

Or use Node:

```bash
npx http-server -p 8000 .
```

## First-time deployment

If this repo doesn't have a remote yet, here's the full setup:

1. **Create a public GitHub repo** named `peptidly-website` under your account.
   Do NOT initialize with a README from the GitHub UI — we'll push our own.

2. **Push the local files:**
   ```bash
   cd path\to\peptidly-website
   git init
   git add .
   git commit -m "initial commit"
   git branch -M main
   git remote add origin https://github.com/<your-username>/peptidly-website.git
   git push -u origin main
   ```

3. **Enable GitHub Pages:**
   - Repo → Settings → Pages
   - Source: **Deploy from a branch**
   - Branch: **main**, folder: **/** (root)
   - Save

4. **Verify the temporary URL works:** `https://<your-username>.github.io/peptidly-website/`

5. **Configure custom domain** (Settings → Pages → Custom domain): `peptidly.co.uk`

6. **Configure DNS at Namecheap:**
   - Domain List → Manage `peptidly.co.uk` → Advanced DNS
   - Delete any default records
   - Add four A records for the apex (`@`):
     ```
     @  A  185.199.108.153
     @  A  185.199.109.153
     @  A  185.199.110.153
     @  A  185.199.111.153
     ```
   - Add CNAME for `www` → `<your-username>.github.io`
   - Save and wait for DNS propagation (5 min to a few hours)

7. **Wait for HTTPS** to provision in Settings → Pages, then check **Enforce HTTPS**.

8. **Verify:** `https://peptidly.co.uk/privacy` should load.

## Notes

- No cookies. The home and calculator pages load one third-party script, Umami (`cloud.umami.is`), which counts visits and clicks on the Google Play links on `peptidly.co.uk` only (`data-domains`, so local test runs are not counted); nothing else is loaded from another domain, and the fonts are self-hosted.
  The landing page runs a small script with no dependencies (`home.js` and `calc.js`), and the
  unsubscribe page calls the Supabase edge function. The legal pages use the system font stack.
  The landing page is about 140 KB on first load, most of it the two font files.
